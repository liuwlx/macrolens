# 数据概览页 UI 字符图纠正报告

## 1. 问题与场景

前一版错误地把用户指定的中文 UI 字符线框图改写成了英文结构规格。用户需要的是参考图中可直接放进重构计划的中文字符图，包含现有 MacroLens 顶部导航、全站侧边导航、指标树、明细数据表、指标详情和底部分析区。

## 2. 分析过程

重新打开用户指定图片并逐区核对文字、分隔线、列关系和纵向延续关系，不再替换用户指定的表达形式，也不擅自更改图片中标明的桌面端断点 `≥1280px`。

确认的布局含义：

- 顶部导航和左侧导航继续使用现有 MacroLens 外壳。
- 页面标题区右侧保留收藏入口和面包屑。
- 筛选条位于标题区下方并横跨页面内容区。
- 主工作区为指标树、明细数据表、指标详情三列。
- 指标树在下半部分继续向下延伸。
- 底部分析区从明细表列开始，横跨明细表和指标详情区域。
- 趋势图、贡献分析和统计摘要保持截图中的左右关系。

## 4. 使用的 Agents、Skills、Tools 与文档

- Agents：未使用子 Agent。
- Skills：沿用 Product Design 的截图核对方法。
- Tools：原图查看、补丁写入、Git 差异检查。
- 文档：`AGENTS.md`、`.codex/organization.toml`、`docs/organization/README.md`。
- 设计依据：用户提供的 `codex-clipboard-e70316c8-1620-4bf3-8862-d2309bf2517e.png`。

## 5. 值得沉淀的经验与模式

- 用户指定“UI 字符图”时，应保留其语言、信息密度和表达形式，不能擅自改写成组件架构图。
- 纠正请求应先确认用户指向的具体图片，再修改已有交付物。
- 字符图用于产品共同理解，结构精确度优先于额外的工程推导。

## 6. 更好的初始提示词

> 请把这张图片里的中文 UI 字符图原样整理成可复制的 Markdown 代码块，保留现有顶部导航、全站侧边导航、三列主工作区和底部分析区，不要改写成英文架构图，也不要擅自改变断点。

## 7. 更优方案与提示词

更优方案是把用户给定的字符图作为主版本，仅在图后补充简短的结构说明，避免把补充说明混进字符图本身。

> 请逐行核对我提供的 UI 字符图截图，输出一份中文等宽字符版；随后只补充“区域关系”和“响应式变化”两段说明。原图中的名称、断点和布局关系均视为已确认，不要自行替换。
