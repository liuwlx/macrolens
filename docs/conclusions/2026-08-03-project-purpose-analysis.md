# MacroLens 项目用途分析工作报告

日期：2026-08-03

## 1. 本次遇到的问题及场景

用户希望在没有预设技术背景的情况下，仔细阅读并分析整个项目，明确回答“这个项目是干什么的”。这类问题不能只复述 README，需要同时判断产品定位、目标用户、核心业务流程、技术架构、数据可信机制，以及当前实现究竟是原型、完整产品还是仍有上线条件的候选版本。

## 2. 分析过程

分析按以下层次展开：

1. 阅读根目录、README、构建清单和验收报告，形成初步产品定位。
2. 阅读架构、数据源、许可、验收等文档，确认系统边界和非功能要求。
3. 检查 Next.js 页面和 API 客户端，确认用户真正能够操作的产品模块。
4. 检查 FastAPI 路由和 SQLAlchemy 模型，确认后端领域与数据结构不是空壳。
5. 检查 Scheduler、Worker、Provider 同步、文档处理和 AI 任务，确认后台链路的实际行为。
6. 对照运行时报告和构建清单，区分“代码已实现”和“生产环境已验证”两种状态。

## 3. 解决问题的工作流程

本次采用“产品表面 → 业务能力 → 数据链路 → 工程实现 → 上线状态”的工作流：

- 产品表面：盘点首页、数据、日历、FOMC、文档、AI、对比、工作区、收藏、提醒、报告和管理后台。
- 业务能力：确认指标检索、转换、修订、数据血缘、发布事件、研究资料、AI 引用、项目沉淀和成果交付。
- 数据链路：确认官方来源抓取、原始响应保存、标准化、质量门禁、不可变 vintage、latest 投影和批次回滚。
- 工程实现：确认 Web、API、Worker、Scheduler、PostgreSQL/pgvector、对象存储和邮件测试服务的职责。
- 状态判断：结合已执行测试与剩余上线门禁，将项目定义为“实现较完整的生产候选版”，而不是已完成真实生产验证的在线服务。

## 5. 值得沉淀的经验和模式

### 5.1 理解项目不能只看 README

README 能说明愿景，但实际用途需要由页面、路由、模型和后台任务共同验证。尤其要检查前端是否连真实 API、后台是否有真实任务分发、核心表是否表达了业务约束。

### 5.2 宏观数据产品的核心不是画图，而是时间与来源语义

MacroLens 最有价值的设计不是图表数量，而是：历史版本不可覆盖、最新值只是服务投影、每条数据都有来源血缘、派生指标有公式版本、预期值是时间快照。这些规则让研究结论可以回溯到“当时知道什么”。

### 5.3 “可访问”不等于“可再分发”

项目把网页展示、下载、API 再分发、AI 上下文和 AI 训练拆成独立许可开关，这是数据平台中值得复用的合规模式。

### 5.4 AI 研究能力需要冻结证据与校验引用

AI 并不直接访问数据库，而是使用经过权限和许可检查的上下文快照；生成后再校验引用编号。这比单纯把数据库搜索结果塞给模型更容易审计和复现。

### 5.5 必须区分代码验收与环境验收

测试、静态检查和模拟 Provider 通过，只能证明代码候选版本具备相应能力。真实 API、商业授权、云资源、备份恢复、容器端到端和渗透测试仍是上线前独立门禁。

## 6. 反推的更好初始提示词

> 请完整阅读这个项目的 README、架构文档、前端页面、后端 API、数据库模型和后台任务，然后用产品经理也能理解的语言说明：它服务谁、解决什么问题、用户能完成哪些核心工作、数据从哪里来并如何保证可信、AI 在其中做什么、采用什么技术架构，以及目前是原型、生产候选还是已经可上线。不要只复述 README，请用代码交叉验证每项结论，并指出尚未完成或依赖外部条件的部分。只做分析，不修改业务代码；最后按 AGENTS.md 生成工作报告。

## 7. 当前场景下更优方案与对应提示词

更优方案是在用途分析之外，增加一份“功能—证据—成熟度”矩阵。每项产品能力都绑定前端页面、API、数据模型、Worker 或测试证据，并标记为“已实现、需配置、需授权、需真实环境验收”。这样可以避免把代码中的接口误判为已经可用的生产能力，也能让后续接手者快速决定下一步。

对应提示词：

> 请对这个代码库做一次以“产品用途与成熟度”为目标的系统审阅。先用一句话定义产品，再分别说明目标用户、典型工作流、核心模块、数据生命周期、AI 工作方式、许可与安全边界、部署架构。随后制作“功能—代码证据—当前成熟度—上线缺口”矩阵；所有判断必须由实际页面、API、模型、Worker、测试或验收文档支撑。明确区分代码已实现、需要环境配置、需要人工数据映射、需要商业授权和需要真实生产验收的内容。不要修改业务代码，最后依照 AGENTS.md 把分析过程写入 `docs/conclusions`。

## 最终结论

MacroLens 是面向宏观研究员的美国宏观经济研究与数据运营平台。它将官方宏观指标、历史修订、经济发布日历、FOMC 材料、文档检索、跨指标分析、个人研究工作区、提醒和带可验证引用的 AI 分析整合在一起。其关键差异化能力是可追溯的数据 vintage、来源血缘、质量门禁、许可控制和可审计的 AI 上下文。

从代码和验收材料看，它已不是单文件原型，而是由 Next.js Web、FastAPI API、PostgreSQL/pgvector、Worker、Scheduler 和对象存储组成的较完整生产候选版本。但它不能被描述为已经完成生产上线：真实 Provider 密钥与响应、30 条非 READY 数据映射、商业数据授权、网络化前端构建、PostgreSQL/容器端到端、Terraform、备份恢复和安全测试仍需在目标环境完成。
