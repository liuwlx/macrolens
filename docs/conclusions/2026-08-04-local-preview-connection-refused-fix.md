# 本地预览连接拒绝修复报告

## 1. 问题与场景

用户在 Chrome 中访问 `localhost` 时看到 `ERR_CONNECTION_REFUSED`。数据概览页面已经完成构建，但此前用于验收的前端与模拟 API 运行在临时命令会话中；会话结束后进程被回收，因此浏览器无法建立连接。

## 2. 分析过程

先以 `http://127.0.0.1:3000/data` 为最小复现入口，并检查本机 `3000`、`4010` 端口。初始检查确认两个端口均未监听，HTTP 请求稳定复现连接拒绝。随后核对相关进程，未发现仍在运行的 MacroLens Web 或模拟 API，排除了页面路由错误和端口漂移，最终定位为预览服务生命周期依附于临时执行会话。

按优先级验证的假设为：

1. 临时预览进程随会话结束被回收（已确认）。
2. 应用启动后异常退出（未发现残留进程或新崩溃证据）。
3. 应用监听了其他端口或地址（端口扫描未发现相关监听）。

## 3. 解决流程

1. 新增 `artifacts/design-qa/local-preview-server.mjs`，在一个 Node.js 进程内启动模拟 API 和 Next.js 生产构建。
2. 先在受控会话中启动脚本，验证 `/data` 能返回 200 且包含 MacroLens 页面内容。
3. 精确核对测试进程的 PID、可执行文件、命令行和监听端口后，停止测试进程。
4. 通过 Windows CIM 创建独立后台进程，使服务不再依赖临时命令会话。
5. 验证后台进程同时监听 `127.0.0.1:3000` 与 `127.0.0.1:4010`。
6. 连续两轮访问页面与 API 健康端点，页面、品牌内容和 API 均通过验收。

## 4. Agents、skills、tools 与文档

- Agents：主 Agent `/root`；本次为单机运行态修复，未启用子 Agent。
- Skill：`diagnosing-bugs`，用于执行复现、假设排序、最小修复和回归验证闭环。
- Tools：`exec_command`、`apply_patch`；PowerShell 的 `Get-NetTCPConnection`、`Get-CimInstance`、`Invoke-CimMethod`、`Invoke-WebRequest`；Git 状态检查。
- 文档：项目根目录 `AGENTS.md` 中的工程规则与总结要求；`diagnosing-bugs/SKILL.md`。

## 5. 值得沉淀的经验与模式

- 本地验收链接是否可用，不只取决于代码和构建，还取决于服务进程是否拥有独立、持续的生命周期。
- 在交付 `localhost` 链接前，必须验证端口监听、页面 HTTP 状态、关键页面内容和依赖 API，并至少连续检查两次。
- 停止旧进程前应同时核对 PID、可执行文件、命令行和预期监听端口，避免误伤其他本地服务。
- 将前端和验收用 API 收敛到单一预览进程，可减少启动顺序、进程遗失和端口状态不一致的问题。

## 6. 更好的初始提示词

“我访问 `http://localhost:3000/data` 出现 `ERR_CONNECTION_REFUSED`。请检查本地前端和所需 API 是否真的在运行，定位原因并修好；启动方式要在你的临时命令结束后仍能保持运行，最后连续验证页面和 API 都返回 200，并把可直接打开的链接给我。”

## 7. 更优方案提示词

“请为当前项目建立一个可靠的本地验收启动方式：复用现有生产构建，用一个可独立后台运行的进程同时启动 Web 与模拟 API；启动前安全识别冲突端口，启动后检查进程、端口、页面关键内容和 API 健康端点，连续两轮通过后再交付验收链接，并说明重启电脑后的恢复方式。”
